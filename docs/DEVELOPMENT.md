# 개발 노트

이 앱을 고치거나 빌드할 때 필요한 내용. 쓰는 법은 [README](../README.md) 를 본다.

## 실행

```powershell
npm install
npm run dev      # 개발 (위젯 창 + http://localhost:5173 미리보기 동시)
npm run build    # 프로덕션 번들
npm run dist     # exe 패키징 → release/
```

`npm install` 시 npm 정책으로 설치 스크립트가 보류되면:

```powershell
npm approve-scripts electron koffi esbuild
node node_modules/electron/install.js   # 이미 설치된 패키지는 수동 실행 필요
```

### 브라우저 미리보기

`npm run dev` 중 크롬에서 `http://localhost:5173` 을 열면 위젯과 같은 화면이 뜬다.
`window.widget` 이 없으면 `lib/bridge.ts` 가 localStorage 목으로 자동 대체하고,
샘플 데이터를 깔아준다. 우하단 버튼으로 밝은/어두운/사진/복잡한 배경을 바꿔가며
유리 질감을 확인할 수 있다. HMR 로 즉시 반영되므로 디자인 반복에 쓴다.

## 알아둘 것

**바탕화면 고정** — Electron 에 벽지 레벨 API 가 없어서 koffi 로 Win32 를 직접 부른다.
`WS_EX_NOACTIVATE` 는 **쓰지 않는다**. 그걸 걸면 창이 활성화되지 않아 일정 제목을
타이핑할 수 없다. 대신 포커스를 잃을 때 `HWND_BOTTOM` 으로 가라앉히고 3초마다 재적용한다.
`WS_EX_TOOLWINDOW` 로 Alt+Tab·작업표시줄에서는 뺀다.

**Win+D** — '바탕화면 보기'는 모든 창을 최소화한다. 위젯은 바탕화면 소속이므로
`minimize` 를 받으면 즉시 복원하고 다시 가라앉힌다.

**배경 밝기 자동 대응** — 흰 유리는 어두운 배경화면 위에서 회색 떡이 된다.
`SystemParametersInfoW` 로 배경화면 경로를 얻어(레지스트리 `reg.exe` 는 한글 경로에서
코드페이지가 깨진다) 위젯이 놓인 자리의 평균 휘도를 재고, 임계값 근처에서 떨리지 않게
히스테리시스를 둔다. 20초마다 경로+수정시각만 확인하고, 바뀐 경우에만 디코딩한다.
설정에서 자동/밝게/어둡게로 고정할 수도 있다.

**크기 조절** — 칸에 보이는 항목 수는 `ResizeObserver` 로 실제 줄 높이를 재서 정한다.
`MonthGrid` 의 `ITEM_H`/`HEAD_H` 는 CSS 의 `.it`/`.cell-head` 높이와 맞춰야 한다.
칸이 84px 보다 좁아지면 근무시간 배지를 아랫줄로 내리고 `10:00~19:00` → `10~19` 로 줄인다.

**메모장** — 오른쪽에 붙는 자유 메모. 펼치면 창 자체가 메모장 폭만큼 넓어져서
(main 의 `window:notes`) 달력이 좁아지지 않는다. 화면에 자리가 없으면 넓히지 않고
달력이 대신 줄어든다. 타이핑마다 파일을 쓰지 않도록 500ms 모았다 저장한다.
쪽지 배경은 5색(노랑/분홍/민트/파랑/연보라) 중에 고른다 — 기본은 노란 메모지.

왼쪽 경계를 끌면 폭이 바뀐다(200~560). 이때는 창 크기를 건드리지 않고 달력과 나눠 갖는다
— 경계를 끄는 건 "둘 사이에 공간을 배분한다"는 뜻이지 창을 키우겠다는 뜻이 아니다.
끄는 동안은 화면만 따라오게 하고 손을 뗄 때 한 번 저장한다.

**메모의 마크다운** — 평소에는 렌더된 결과를, 누르면 원본을 보여준다.
늘 원본만 보이면 `- [ ]` 같은 기호가 노출되어 읽기 나쁘고, 늘 렌더만 하면 고칠 수 없다.

파서는 직접 짜지 않고 marked + DOMPurify 를 쓴다. 이스케이프와 중첩 목록 처리는
생각보다 까다롭고 거기서 실수하면 붙여넣은 내용이 그대로 실행될 수 있다.

`ALLOWED_URI_REGEXP` 는 `href` 뿐 아니라 `type` 에도 적용된다. 그대로 두면
체크리스트의 `type="checkbox"` 가 URI 검사에 걸려 지워지고, type 없는 `<input>` 은
텍스트 입력창으로 그려져 목록이 통째로 망가진다. `ADD_URI_SAFE_ATTR: ['type']` 로 뺀다.

허용 속성에서 `disabled` 는 일부러 뺐다. marked 는 체크박스에 기본으로 `disabled` 를
붙이는데, 비활성 입력은 클릭 이벤트를 아예 흘리지 않아 눌러도 반응하지 않는다.

**체크박스 토글** — 렌더된 체크박스를 누르면 원본 마크다운의 `[ ]` 가 함께 바뀐다.
화면의 몇 번째 체크박스인지만 세면 되는데, marked 가 원본 순서대로 위에서 아래로
그리므로 순번이 그대로 대응된다(`toggleTask`). 브라우저가 제 마음대로 체크 상태를
바꾸지 않게 `preventDefault` 하고, 다시 그린 결과로만 반영한다.

**이모지** — 입력은 Windows 기본 입력기(`Win` + `.`)를 쓰면 된다. 다만 한글 폰트에는
이모지 자형이 없어서 폰트 스택 뒤에 `Segoe UI Emoji` 를 붙여야 흑백 자형이나
네모로 떨어지지 않는다.

**글꼴** — **Jua** 하나로 간다. 로컬 번들이라 인터넷 없이 뜬다.

Jua 는 굵기가 400 하나뿐이다. 400/600/700 이 **픽셀 단위로 동일하게** 그려진다
— 가짜 굵게(synthetic bold)조차 걸리지 않으므로 `font-weight` 로는 아무것도 구분되지 않는다.
달력은 색·모양·크기가 구분을 떠받치므로 문제없다. 굵기에 기대던 곳은 메모의 `**굵게**`
하나뿐이라 거기만 색으로 대신한다(`.note .md strong`).

`line-height: 1` 이면 Jua 의 글자 잉크가 줄 높이에 꽉 차서 윗부분이 잘린다.
`.it` 높이를 16px, 행간을 1.3 으로 잡았다(`MonthGrid` 의 `ITEM_H` 와 맞춰야 한다).
자간도 Jua 가 빡빡해서 조금 풀어 놓았다.

한글 폰트에는 이모지 자형이 없다. 폰트 스택 뒤에 `Segoe UI Emoji` 를 붙여야
흑백 자형이나 네모로 떨어지지 않는다.

(후보 비교용 폰트 스위처가 미리보기에 있었는데 고른 뒤 지웠다. 후보는 Gothic A1 /
IBM Plex Sans KR / Spoqa Han Sans Neo / Sunflower / Dongle / 고운돋움 이었다.
Dongle 은 굵기가 3단계라 기대했지만 폭이 Pretendard 의 57% 라 10.5px 본문에서 못 읽는다.)

**말풍선** — 브라우저 기본 `title` 툴팁은 Win32 회색 상자로 그려져 위젯과 따로 논다.
`title` 대신 `data-tip` 을 쓰고 `components/Tooltip.tsx` 에서 직접 그린다.
칸이 수십 개라 항목마다 리스너를 달지 않고 문서 전체에서 한 번만 듣는다.
첫 줄은 내용, 둘째 줄부터는 조작 안내로 한 단계 흐리게 보여준다.

**투명도를 두 단계로** — 투명도를 위젯 전체에 CSS `opacity` 로 한 번에 걸면
자식이 부모보다 진해질 수 없다. 메모는 글을 읽는 물건이라 달력보다 진해야 해서,
유리 배경을 `.widget::before` 로 떼어내고 `--live-opacity` 를 세 군데
(`::before` / `.main-col` / `.notes`)가 각자 다르게 쓴다.
메모장은 `min(1, calc(var(--live-opacity) + 0.28))`.

어두운 배경화면 위에서는 같은 알파라도 훨씬 더 비쳐 보인다.
그래서 다크 팔레트의 `--glass` 는 밝은 쪽(0.66)보다 오히려 더 불투명한 0.88 이고,
쪽지도 알파를 훨씬 높게 잡았다.

`+ 메모` 를 누르면 새 쪽지에 커서가 가야 하는데, '처음 보는 id 인가' 를 렌더 중에
판정하면 안 된다. StrictMode 가 렌더를 두 번 돌려서 두 번째 패스에 이미 본 것으로
처리되고 포커스를 놓친다. 누른 시점에 플래그를 세우는 방식으로 처리했다.

**항목 수정** — 달력 칸의 항목을 두 번 클릭하면 `DayEditor` 가 수정 모드로 바뀐다.
칸 안에서 인라인 편집을 하지 않는 이유는 줄 높이가 14px 라 너무 옹색하고,
삭제 버튼을 그 크기에 두면 잘못 누르기 쉽기 때문이다.
일정↔할 일 변환은 지원하지 않는다 (날짜 이동은 드래그로 한다).

브라우저는 더블클릭 전에 클릭을 두 번 흘린다. 그대로 두면 할 일을 두 번 눌렀을 때
완료가 두 번 뒤집힌 뒤 수정창이 뜬다. 그래서 단일 클릭 동작만 `CLICK_DELAY` 만큼
미뤄뒀다가 더블클릭이 오면 취소한다. 체크박스를 직접 누른 경우는 즉시 반응해야 하므로
지연 없이 바로 토글한다.

**드래그로 날짜 이동** — 항목을 다른 칸에 떨구면 그 날짜로 옮긴다. 시간과 완료 상태는 유지된다.
끌리는 항목은 `dragRef` 와 state 두 군데에 둔다. `dragover` 중에는 브라우저가
`dataTransfer` 를 못 읽게 막으므로 무엇이 끌려오는지 따로 기억해야 하는데,
state 만 쓰면 `dragstart` 직후의 `drop` 이 아직 반영 안 된 옛 값을 본다.
판정에는 즉시 갱신되는 ref 를, 강조 표시에는 state 를 쓴다.

**커서** — 달력 안에서는 커서 모양을 바꾸지 않는다(`.grid-viewport *`).
칸을 훑을 때마다 화살표/손가락/쥐는손이 번갈아 바뀌면 산만하다.
클릭할 수 있다는 건 배경이 밝아지는 것으로 알린다.

**저장** — temp 파일 → rename 으로 원자적으로 쓴다. 저장 중 강제 종료해도 안 깨진다.
위치는 `%APPDATA%\calendar-widget\data.json`. 재부팅해도, 앱을 지워도 남는다.
스키마가 바뀌면 `store.ts` 의 `migrate()` 가 열 때 메워준다
(v1→v2 할 일에 날짜 부여, v2→v3 메모 배열 추가).
없는 필드는 전부 기본값으로 채우므로 예전 파일도 그대로 열린다.

**패키징** — koffi 는 네이티브라 `asarUnpack` 으로 빼야 하고, 트레이 아이콘은
`extraResources` 로 asar 밖에 둬야 읽힌다. 둘 다 `electron-builder.yml` 에 있다.

## 밟았던 함정

같은 실수를 다시 하지 않으려고 적어 둔다.

**`reg query` 경로의 백슬래시** — `'HKCUControl PanelDesktop'` 으로 쓰면
`C` 와 `D` 가 이스케이프로 먹혀 `HKCUControl PanelDesktop` 이 된다. 쿼리가
조용히 실패하고 늘 기본값(10, fill)으로 떨어지므로, fit/stretch/center 를 쓰는
사람은 배경화면의 엉뚱한 영역을 재게 된다. 반드시 `\` 로 쓴다.

**`did-finish-load` 를 `ready-to-show` 안에서 걸기** — 보통 이미 끝나 있어서
`once()` 가 영영 안 불린다. `isLoading()` 으로 갈라야 한다.

**수정 시작 시점의 사본을 그대로 저장하기** — `editing.item` 은 그 뒤의 변화를
모른다. 수정 중에 체크한 완료 상태나 드래그로 옮긴 날짜가 저장할 때 되돌아간다.
저장 직전에 현재 값을 다시 찾아 그 위에 얹는다.

**'요청했음' 플래그로 새 항목 감지하기** — 플래그를 세운 직후 렌더에서 목록 길이는
이미 0 이 아니므로, 새 항목이 도착하기 전에 플래그가 꺼진다. 브라우저 목은
마이크로태스크라 우연히 통과하지만 실제 IPC 에서는 늘 늦는다. 누르기 전의 id 집합을
기억해 두고 거기 없는 것을 새 항목으로 본다(`NotesPanel` 의 `seenIds`).

**드래그 리스너를 부모가 만든 콜백에 매어두기** — 부모가 렌더마다 새 화살표를 만들면
`useEffect` 정리 함수가 드래그 도중에 돌아 리스너를 떼어 버린다. ref 로 최신 콜백만
가리키고, 리스너 등록/해제는 신원이 고정된 함수로 한다.

**메모리를 먼저 바꾸고 디스크에 쓰기** — 쓰기가 실패하면 캐시와 파일이 어긋난다.
`rename` 전에 `fsync` 도 해야 원자성이 실제로 성립한다.

**`opacity` 를 위젯 전체에 걸기** — 자식이 부모보다 진해질 수 없다.
배경 레이어를 `::before` 로 떼어내야 부분마다 다른 불투명도를 줄 수 있다.

**`title` 속성** — Win32 회색 상자로 그려져 위젯과 따로 논다. `data-tip` + 직접 그리기.

**`slider` 의 `onChange`** — 끄는 동안 초당 수십 번 불린다. 그때마다 파일을 통째로
동기 쓰기 하면 main 이 멈칫거린다. 화면은 CSS 변수로 즉시, 저장은 손을 뗄 때 한 번.
